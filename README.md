# CS-255-DriverPass-Project
This repository contains the business requirements and system design documentation for DriverPass, developed for a client named Liam in SNHU’s CS-255: Systems Analysis and Design course. The project focuses on creating a web-based system to help students prepare for DMV driving exams through online practice tests, in-person lesson scheduling, and instructor progress tracking.

The design also includes administrative tools for managing lesson packages, handling secure payments, and assigning user access levels. This project highlights my ability to translate client needs into clear, organized UML diagrams and structured requirements that support both technical implementation and client understanding.

**Skills Demonstrated:** Systems Analysis • UML Modeling • Requirements Gathering • Process and Object Modeling • Client-Focused Design

---

## **Reflection Journal**

The DriverPass project was created for a client named Liam, who wanted a web-based system to help students prepare for their DMV driving tests. His vision was to give students access to online practice exams, allow them to schedule in-person driving lessons, and help instructors track progress more efficiently. He also wanted to make administrative work easier by including features for managing lesson packages, handling secure payments, and giving each user the right level of access within the system.

One area where I feel I did especially well was translating the client’s needs into clear, organized UML diagrams. I focused on showing how students, instructors, secretaries, and administrators interact within the system, and how each of their actions connects to the overall process. The class and use case diagrams were particularly effective in helping me visualize relationships between different components, while also making it easier for nontechnical audiences to understand how the system functions. I’m proud of how well these diagrams and my written documentation came together to form a complete, logical design.

If I could revise one part of my work, I would refine my activity diagrams to show more detail about how the system handles different outcomes. For example, I would add steps for situations where a student cancels a lesson, or when a payment does not go through successfully. Including those alternate paths would make the diagrams more realistic and provide better guidance for developers who might later implement the design.

When interpreting the user’s needs, I relied heavily on the DriverPass interview transcript to identify what the client truly valued. Efficiency, security, and flexibility were the main priorities. I incorporated these into the design by giving each user role a specific set of permissions and tools that matched their responsibilities. Students could schedule and take tests, instructors could record progress, and administrators could oversee users and reports. Focusing on the user’s experience made the system more intuitive and practical. Considering user needs is essential in software design because even the most technically advanced system is only successful if it actually helps people do their work more easily.

My approach to designing software always begins with understanding the problem before thinking about solutions. Once I know the requirements, I start modeling the system visually with UML diagrams to organize relationships and workflows. I find that seeing everything mapped out helps me identify gaps or inefficiencies early. I also believe in using an iterative approach, breaking projects into smaller, testable parts and collecting feedback at each stage. Going forward, I plan to continue combining user-centered thinking with structured modeling to design systems that are both functional and easy to use. This project helped me strengthen those skills and reminded me how important communication and clarity are in every stage of system design.
